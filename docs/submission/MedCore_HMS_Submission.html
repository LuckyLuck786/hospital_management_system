1. Overview

MedCore HMS digitises the complete hospital workflow — registration, appointment scheduling, the doctor's encounter (vitals, diagnosis, e-prescription, lab orders), laboratory processing, pharmacy dispensing, ward and bed management, billing with online payments and insurance/TPA claims, and real-time notifications — in one secure, role-aware platform. Each hospital is an isolated tenant of a single SaaS deployment, so it serves anything from a 30-bed clinic to an 800-bed multi-speciality chain. All nine roles from the brief (Super Admin, Hospital Admin, Doctor, Nurse, Receptionist, Lab Technician, Pharmacist, Accountant, Patient) have their own dashboard and enforced API permissions.

4. Architecture & key design decisions

  • Row-level multi-tenancy: every hospital-owned table carries hospitalId; a Tenant guard pins each request to the caller's hospital and services re-check ownership, so guessing another hospital's record ID returns 403.
  • Request pipeline: Helmet → rate limiting → strict CORS → JWT guard → Roles guard → Tenant guard → validation → service → Prisma; responses use one envelope { success, data, meta } / { success:false, error:{ code, message } }.
  • Concurrency: partial unique indexes guarantee that only one of two simultaneous bookings for a slot succeeds (409 for the other) — safe across multiple API instances without row locks.
  • Caching: Redis stores refresh tokens per device (rt:{userId}:{deviceId}), doctor availability for 60 s with invalidation on every booking, reminder de-duplication and BullMQ queues.
  • Data model: 34 Prisma models normalised to 3NF with 8 migrations — weekly schedule templates, prescription line items, structured lab results with reference ranges, medicine batches, individual beds, pre-authorisations, insurance claims, vital signs, vaccinations and an audit log. Soft deletes on patients, doctors and appointments.
  • Deployment: Next.js frontend on Vercel rewrites /api to the NestJS API on Railway (same origin, no CORS for REST); WebSockets connect directly. The API container runs database migrations on start-up. Docker Compose + Nginx reproduce the stack locally.

5. Security

  • bcrypt (cost 12) password hashing
  • 256-bit JWT secrets; refresh-token rotation with replay rejection
  • 100 req / 15 min on auth routes, 1000 req / 15 min on the API
  • Helmet headers, strict CORS allow-list, HTTPS everywhere
  • SameSite=Strict httpOnly refresh cookie; Bearer tokens for writes
  • AES-256-GCM encryption of diagnosis, notes and treatment plans
  • Audit log for every write with redacted request bodies
  • Log sanitiser — passwords, tokens and OTPs never logged
  • Upload allow-list, magic-byte checks, private storage, signed URLs
  • Ownership checks on users, schedules, stock, records and claims
